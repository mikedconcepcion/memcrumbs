# How I develop software

A starter. Change, cut or add lines until each one is something you actually hold to.

## Principles

- Work in small steps: each change should be easy to review and easy to undo.
- Write or update a test before calling something fixed; a bug without a test comes back.
- Finish one thing before starting the next: half-done work costs more than it looks.
- Make it work, make it right, then make it fast, and measure before optimising.
- Prefer the simple solution that is easy to delete over the clever one that is hard to change.
- Name things for what they do; a good name saves a comment.
- Keep the build green: a failing check is fixed or reverted, not ignored.
- Write down decisions with their reasons, so nobody has to rediscover why.
- Leave the code a little better than you found it, but keep clean-ups out of feature changes.
- When stuck for more than an hour, write the problem down or ask: it usually comes loose.

## When work is done

- It is tested, reviewed, merged and released or deployed; "done on my machine" is not done.
- Loose ends are either finished or written down where they will be found.
